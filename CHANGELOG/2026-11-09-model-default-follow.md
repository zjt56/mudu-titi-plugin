# 修改全局默认模型时，下方子 Agent 与审核轮次一起跟随

## 背景

用户反馈：在「大模型配置」里修改全局默认大模型时，下面的子 Agent / 审核轮次没有跟着改过来。界面下拉仍显示旧模型，看起来默认改了、下游没改。

## 原因

- 子 Agent 与审核轮次的条目在保存时会被写成**显式** provider/model（等同当时默认值），因此“跟随默认”在保存后变成了一条具体覆盖；之后改全局默认只更新 `default`，这些条目仍指向旧模型，`router/route_pick` 也优先使用它们。
- 这是本次修复前的真实行为差异；旧测试只断言“角色优先于阶段并回落到默认”，未覆盖“改默认后旧条目应一起跟随”。

## 改了什么

- `lib/client.js`：`setDefault` 在全局默认**确实变化**时，删除所有仍等于旧默认值的 `stages`/`roles` 条目和 `review.rounds` 条目，使它们重新“跟随默认”；已单独指定为其它模型的条目保持不变。默认值未变时不删除任何条目。默认模型卡片下补充一句行为提示。
- 新增 `backend/model-default-follow.test.cjs`：用真实 `lib/client.js` 的 `setDefault` 片段验证
  1. 改默认后旧默认条目被清除、显式其它模型保留；
  2. 选同一默认不误删覆盖。

## 没改什么 / 边界

- 未改变后端解析规则（角色优先、阶段次之、最后回落默认）、模型路由脚本与生效配置写入；未扩展任何静默兜底。
- 未修改用户已有配置数据；只有下一次在界面改默认时才会据此清理旧镜像条目。用户若希望某子 Agent 继续用旧模型，可单独再指定一次。
- 属插件前端行为修复，**需重载插件/重开面板后生效**（宿主前端 bundle 需重新构建或刷新）。

## 如何验证

- `node --test backend/model-default-follow.test.cjs backend/sub-agent-roles.test.cjs` → **6 项全部通过**。
- `node --check lib/client.js lib/index.js` 通过。
