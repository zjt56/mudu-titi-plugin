# 2026-11-09 答案格式容错审查问题修复

## 背景 / 触发

用户要求拉取仓库并和本地核对，审查 `d2fc74d` 的答案容错修改，随后要求“修复并完善”。本地与远端一致，审查复现四项边界问题：来源换行导致内部句号单边消失、HTML 上下标被删成普通数字、格式归一化后为空的答案误放，以及带尝试身份的真实调用错误被诊断过滤。

## 改了什么

- `app/workflow/agent_tasks.py`：只移除视觉格式标记，保留上下标含义；数字等常用 Unicode 上下标与等价 HTML 写法统一比较，连续同级上下标可合并，已有上下标不会被二次嵌套。来源子串匹配不得切进上下标标记内部，防止普通 `2` 匹配来源的 `²`。
- 答案末尾句号容错不再对每一行执行，保留内部句子边界；同一段答案因 LF/CRLF/`<br>` 换行而排版不同仍等价，小数点保持不变。
- 答案填充和下游来源比较先拒绝归一化为空的非空内容，避免 `.`、`**.**` 或仅含格式标记的输入通过；既有明确缺失占位保持原口径。
- `app/workflow/diagnose.py`：识别顶层和 `artifacts.attempt_dir` 两种真实尝试身份；在本批次、本阶段、本次尝试及时间均有效时，读取完整调用错误或 `task-report.json` 的前置缺项。分别检查每份报告的新鲜度，不能用新日志复活旧错误。已成功导入或最新修复轮无失败时不再显示历史错误。
- 补充来源校验与下游比较双向回归、上下标部分匹配防护、空内容拒绝，以及真实错误 envelope/缺项报告回归。同步 `app/docs/pipeline.md`。
- 全量回归发现文档制度的既有缺项：上次答案记录标题缺少“改了什么”，以及远端音频/审核历史记录未进入索引；补齐标题和索引，不改这些功能实现。

## 没改什么 / 边界

继续接受不影响含义的加粗、画线、空白、引号和全半角格式差异；不做语义改写，不删除审核差异，不改变上传/发布边界，不直接编辑真实批次台账或产物。本轮只读核对2023安徽卷的正式81道答案和34个单元，答案阶段仍为 completed。
