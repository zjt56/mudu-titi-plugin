# 2026-11-12 原卷预览：图片选项 A/B/C/D 按选项标签正确配对（图在前也认）

## 1. 背景 / 触发

用户截图 04 课时第4题预览：镊子(image14) 被当成题干大图，选项只显示 A汤匙/B餐叉/C餐刀——
image14 从选项里丢失、其余错位一格。数据层（batch.json attachments）已正确
(A→image14…D→image17)，问题在**前端预览渲染** `lib/client.js::renderBlocks`：
其选项成组逻辑只认「标签→图」(`A.[IMG]`)，不认「图→标签」(`[IMG]A.`)，导致图片前置
选项题的图被当正文大图、其余错位。

## 2. 改了什么

- `lib/client.js::renderBlocks`：选项成组改为**以选项标签为锚**，图跟着标签走——
  每个标签优先配「紧邻的、尚未被消费的图」：前邻是未消费图（图在前 `[IMG]A.`）→ 用前图；
  否则后邻是图（图在后 `A.[IMG]`）→ 用后图。预扫描 labelToImg + consumedImg，主循环
  遇到「有图的选项标签」整排渲染、跳过已消费图。两种排版都正确，letter 由标签决定，
  不再按图出现顺序错配。纯文本选项、正文单图不受影响（不误判为选项行）。

## 3. 没改什么 / 边界

- 只改预览渲染（client.js），不改批次数据、切题、题干/选项/答案。
- 不改变选项标签本身的文本/顺序，仅修正「哪张图属于哪个选项」的展示配对。

## 4. 如何验证

- 逻辑模拟两形态：图在前 `[IMG]A.` → A=image14/B=image15/C=image16/D=image17；
  标签在前 `A.[IMG]` → A=image3/B=image4/C=image5；纯文本选项、正文单图均不被误判。
- 后端 `source_blocks` 对 04 q4 输出块序列正确（题干,image14,A.,image15,B.,...）。
- `node --test backend/*.test.cjs`：255 例，pass 253、fail 0。
- 生效方式：宿主插件前端，需重载 DSH 插件/刷新 GUI 才在界面显示（非 dev:web 不自动热更）。
