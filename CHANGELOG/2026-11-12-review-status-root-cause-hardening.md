# 审核状态深查与防复发

## 触发及结论
用户要求继续深查「一审看着与原标签一致，却标待审核」。针对批次 `04七上人教版课时A计划StarterUnit1Hello!第四课时Projec`，检查了冻结任务、原始响应、安装验收、差异比较、队列及工作台输出。

已证实的问题：
1. 原始一审响应里，u12 的 rationale 明确说「按单项填空/四个选项记录不合理」，assessment 却仍是该值。此前仅验目录合法、来源与覆盖，未检查这种明确自我否定，允许矛盾响应进入比较。只能证明输出矛盾，不能证明模型一定因提示词示例照抄。
2. 前端 `labelAuditPanels` / `hasKnowledgeDiff` 把完整知识点路径截为末级名称，再按数组顺序比较；后端按完整路径集合比较。导致同名不同路径看起来正常、仅顺序不同却标红。这是确定性的前后端口径缺陷。
3. `review_comparison` 没有给 check 提供结构化 `differences`，而 `nodeState` 已有消费该字段的逻辑。因此 verdict=ok 的标签差异会被轮次节点误显示为通过。verdict 不是执行状态：顶层 status=completed 才表示执行完毕，check.verdict 不证明标签与原标注一致。
4. `_review_inputs_key` 漏掉 types、knowledge、answers、嵌套 candidates/units、附件与任务绑定等输入，仅 mtime+size 也不能识别等长且恢复时间戳的替换。详情可能使用新值，总览审核快照仍命中旧值。原有 stale-round 回归失败与此类缓存问题相关；模拟 evaluator 变化不等于真实文件变化，现同时补真实文件变化回归。
5. 上一轮新增维度规则后再次调用 run，没有更新 PROMPT_VERSION，实际第三次 labels 输入仍是旧冻结 prompt。新规则未进入该次调用，因此此前「维度规则解决了该次复跑」的因果说法不成立。
6. 上一轮 A–D 文字硬条件会误伤三选项、图片、共享或听力选项；「选最近合法叶子」有迁就校验风险。

## 修改
- `review_rounds.py`：新导出分片身份加入实际 `_round_prompt`（含角色段）摘要，不再仅靠手工版本号；已导出的在途包保持不可变，不篡改历史任务。
- 收窄无选项提示，明确图片/音频占位不等于无选项；目录映射作为唯一维度口径，无足够证据时 uncertain，不选「最近叶子」凑数。
- 新候选验收增加窄范围 `REVIEW_ASSESSMENT_CONTRADICTION`：只拒绝 rationale 明确否定 assessment 中主类的断言，进入已有失败目标局部补审路径；不修改正式标签、不推断原标签正确、不重写旧轮次。原标签/旧标签的批评不作为自我否定。
- `client.js`：知识点及子类均用完整值集合比较，顺序与重复不产生差异；知识点行保留完整目录分支，空的已提供 assessment 也能显示真实差异；一审理由从实际 check 读取。
- `server.py`：比较输出逐字段 `differences`，供已有轮次状态逻辑区分 ok 与标签一致；详情通过 mark_row 补全差异摘要；重复历史轮次显示 needs_refresh 而非未开始。
- 工作台缓存按 evaluator 声明的 ROUND_INPUTS/ROUND_RULES、审核产物、嵌套草稿、来源附件、留存证据和观察媒体的内容摘要失效；替换 evaluator 时不沿用旧投影。

## 保持边界及排除项
- 本轮只读复验真实批次，没有再次调用模型、重跑整批、自动裁决、改正式标签或改 manifest。
- 一审一致但二审不同，仍是真实差异，必须待审；新执行不自动继承旧执行的人工作决定。不能为减少待审数量合并掉不同观察。
- 二审单题 `roundAssessment.assessment=null` 不是整体不显示：原 UI 已通过 checks 逐条展示，未改成把小题判断外推整组。
- 工作台人工编辑草稿不等于正式审核输入；比较基准保持绑定的正式标签，不把未提交草稿偷偷当成原标签来消除差异。
- 不改变上传/发布授权与闸门口径。
