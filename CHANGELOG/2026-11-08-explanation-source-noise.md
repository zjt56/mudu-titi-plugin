# 2026-11-08 解析来源校验：OCR 噪声与"答案/解析分行"导致的连锁重跑

## 背景 / 触发

用户反馈电脑很卡、且 2023 年安徽卷跑不出结果。排查确认：该批 `explanations` 阶段
每轮 34 分片 × 约 130K 字符全部调模型，被来源校验拒绝后自动重排再跑，已连跑 3 轮，
持续占 CPU。根因不是模型/网络坏，而是来源校验的几类噪声差异导致合法解析被判"未唯一逐字绑定"：

1. 附录被 OCR 加了 `**` 星号、弯直引号混用、全半角逗号混用。
2. 有的答案册把"答案"独立成行、`【解析】` 写在后面一段且不带题号（如 74 题）。
3. 附件材料干净、附录脏，但 SOURCES 优先导致误判。

## 改了什么（`app/workflow/upload_content.py`）

1. `_verbatim` 增补：忽略 Markdown `**`、空白，并把弯引号 `“”‘’`/「」统一为直引号；
   **实词与其余标点（全半角逗号句号等）仍严格保留**，措辞或标点差异仍判为不同。
2. 新增 `STRAY_EXPLANATION` 与"孤立解析归属"扫描：无题号的 `【解析】` 段落绑定到
   上文最近、尚未有解析的编号答案行（不跨结构边界、不覆盖已解析行）。
3. `restore_field` 扩展确定性回填：当 SOURCES 无匹配、而清理后的**附件**片段在
   `_norm` 层面唯一对应一条原文时，回填该权威原文（只做标点/宽度等价，不改实词）。

## 没改什么 / 边界

- 是真改写（加字、改词、概括、截断）仍一律拒绝；新增测试含反例验证。
- 不改审核口径、不上传、不动用户批次。

## 如何验证

- 用该批真实模型响应直接跑 `inspect_content(strict=True)`：58/62/74 与 73-75 组均由
  "未唯一绑定"变为通过，且回填为材料逐字原文。
- `workflow.test_upload_content` / `test_no_ai_generation_rule` / `test_content_labeling`
  / `test_knowledge_content_fallback` / `test_agent_tasks` 共 116 项通过；
  新增 2 个回归用例（孤立解析绑定、引号差异回填）通过。
- 全量逐模块回归结果见下条更新。

## 回退

仅影响来源归一化与回填，可还原 `_verbatim`/`restore_field` 及移除孤立解析扫描。
