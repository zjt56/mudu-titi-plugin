# 2026-11-07 底层执行与恢复内核兼容重构

## 背景

用户授权实施底层优化，同时明确：之前添加的规则不要修改，不要让用户反复重复工作；现有工作流、功能、界面都必须保留。此次以当前包含大量未提交变更的源码为基线，先建立隔离副本和回退快照，再修改与验证。没有重置工作区或覆盖已有未提交工作。

## 改了什么

- [execution_state.py](../app/workflow/execution_state.py)：集中只读执行/质量/本地完成投影；[manifest.py](../app/workflow/manifest.py) 保留原有公开状态常量及函数入口，委托共享实现；[supervisor.py](../app/workflow/supervisor.py) 与 [server.py](../app/workbench/server.py) 使用同一完成契约。最终格式检查未完成时，不提前宣称待提交；任一本地阶段仍需重建时，不误判整批完成。
- [supervisor.py](../app/workflow/supervisor.py)：按持久的最近派发时间公平调度；将本地重试预约与合并显示的自愈冷却分离；只有相关输入确实变化才解除旧自愈冷却。真实 provider 冷却保留。无关的“已延后”标记不能反复重置整批无进展预算；新出现的独立可执行工作仍可继续。
- [self_heal.py](../app/workflow/self_heal.py)：保留动作写入的回退循环守卫，防止最终保存旧台账把它覆盖。记录原故障阶段与修复目标的执行基线，观察所有受支持的排队恢复事件。跨阶段修复只局部排原故障阶段复验，不深度清空下游。上游完成不等于原故障已修复；原故障真实执行并通过新鲜性检查后才记录 verified。
- [local_agent.py](../app/workflow/local_agent.py)：POSIX 子进程继承实际执行锁，父引用关闭不显式解除共享的 flock；减少后端退出而模型进程仍存活时的重复调用。Windows 沿用原有锁行为。
- [server.py](../app/workbench/server.py)：批次列表的重投影不再持有派发/写入全局锁；使用独立读合并锁和写入 epoch 防止旧读回填缓存。接口字段和前端保持兼容；健康接口增加 workflow_runtime_version 供确认实际加载版本。
- [auto.py](../app/workflow/auto.py)：单批轮询尊重 stop_at 前的执行范围；失败、闸门或 busy 等未完成轮次也让出执行时间，避免空转；不改变阶段执行门槛。
