# 2026-11-09 插件端审核防复发：真实进展、派发预算、当前诊断与运维接手

## 背景

用户要求从插件端防止类似「17 年安徽中考英语内部审核反复空转」的故障再次出现，而非只恢复一次批次。此前已修复证据路径归一化造成的 checks mismatch，以及普通审核角色混入轮次输出契约的问题。本次检查其外围调度与恢复链路，发现：

1. 原 review-stall 只在 `_run` 返回后累计，既不约束单次运行内部的无进展循环，也不在后续付费调用之前读取预算。
2. 最后分片来源复验失败仍可能留下 continue 收据，调度以返回值推断进展，反复导出最后分片。
3. supervisor 自动派发经过 server 启动入口时，调用 clear_exhausted，清掉刚累计的尝试与 reservation。
4. 运维发现器把所有 review=needs_review 都视为正常差异，漏接协议与安装停滞；诊断还可能从历史分片失败文件及旧日志取错原因。

## 改了什么

### 审核任务与安装

- `app/workflow/review_rounds.py`：轮次根字段、提示示例、导出示例与 schema 共用结构定义，任务包生成时自检示例；模型返回先校验根结构再进入 pending。并发模式中漏 notes/findings 会带具体缺键反馈在原分片内补答，不把坏响应永久缓存。
- 最终安装在发布整轮记录、重建差异队列和写成功收据之前，先复验绑定来源/原响应/事务。失败抛出 `review_consumer`，保留原始响应与事务，不写成功收据、不发布失败整轮。
- 每次导入后核实对应分片登记或独立轮次验收确实推进。返回 continue 但没有实际进展属于本地消费者故障，不再原样调用模型。
- 失败诊断文件绑定 task_id/input_binding/state_path/零基 part_index/targets，保留具体错误和错误码。历史坏 pending 不反复回放，下一次同任务补答带原失败反馈。

### 重试预算与恢复

- 跨调用预算在派发之前读取，按真实计划、插件审核代码、有效模型配置及显式重启世代隔离；任务 UUID 不构成新问题。返回旧路线不能借切换路线清掉旧预算。
- 消费者故障立即禁止该轮的原样模型调用；其他错误仍保留已有有界反馈重试。另一独立轮次继续执行，已验证分片与样本不回滚。
- 禁止付费重试不禁止本地恢复：先按分片顺序复验保留的事务和 pending；本地证据恢复后可在相同预算范围零模型调用完成安装。真实输入、代码或配置改变时重新计算预算。输入缺失/在途变化仍返回原有 inputs_changed/resumable，不被预算统计遮蔽。
- 持久预算写回与清理使用现有工作流写锁。

### 插件调度、诊断和运维

- `app/workbench/server.py`：自动 supervisor/operations 续跑保留预算与排队 reservation；仅 HTTP 用户继续入口及显式重跑重置 supervisor 预算。
- `app/workflow/operations.py`：review=needs_review 时核验当前两轮执行证据。已完成且有真实差异仍不作为故障接手；协议失败、执行不全、本地安装停滞可以升级接手，不能用缓存 execution_completed 掩盖。
- `app/workflow/diagnose.py`：分片错误绑定当前输入/任务/活动世代，跳过已完成分片和已验收轮次；旧格式错误与阶段日志必须满足当前 started_at，旧错误不能覆盖当前诊断。不删除历史证据。

## 没改什么 / 边界

不补造缺失模型字段、不放宽来源真实性、任务在途哈希、收据不可覆盖或消费者校验。不自动 resolve 真实差异、不改正式标签；审核执行完成仍不等于质量通过。本次没有修改或执行上传/发布，也没有在真实批次中清空任何预算或历史记录。既有 17 项真实差异保持可审核。
