# 同步练习 / 课时同步材料的题型与组题判定口径

本文件说明 `app/references/sync-practice-rules.json` 与 `app/workflow/sync_practice.py`
的用途、边界和扩展方式。这套口径来自 26秋《课时A计划》英语 RJ **七上·八上·九上（学用）正文
854 处大题**的实测归纳，并经用户逐条看图确认。

## 一、适用范围（重要）

只适用于**同步练习册 / 课时同步练习**类材料：

- 按课时编排（`Unit N` + 第 N 课时 + `Section A/B`）；
- 每课时常分**基础段**与**提升段**，提升段题号从 `Ⅰ` 重新开始；
- 典型大题：根据首字母及汉语提示补全单词、根据汉语意思完成句子、单项填空、完形填空、
  阅读理解、任务型阅读、补全对话、选词填空、短文填空、教材语篇回顾、语音题、书面表达。

**不适用**于单元卷、期中期末卷、月考卷、中考真题/模拟卷——这些材料的题型结构与组题
边界由原卷自身决定，不得套用本口径。

## 二、判定内容

一次判定同时给出三件事，避免各批次各自解释：

| 维度 | 取值 | 说明 |
|---|---|---|
| `type` | 27 个主类之一 | 见 `app/references/filter-framework.json` 的 `question_types` |
| `subtype` | 主类的子类 | 必须与目录叶子完全一致，否则不能上传 |
| `kind` | `group` / `standalone` | 共用语篇/对话/表格/方框/图片 → group；每小句独立成题 → standalone |

`unit_kind` 在**结构确认**阶段定死，后续阶段不得改写；本模块只提供判据。

## 三、组题 / 单独题口径（用户 2026-11-11 确认）

**记为 group（整题组）**

- 完形填空、阅读理解、任务型阅读、选词填空、短文填空、教材语篇填空、补全对话；
- 语音题整大题（辨音选择、音标选词、字母表补全、大小写判断、音素归类、歌谣归类）；
- 凡「根据下图 / 根据图片信息 / 图示 / 家谱 / 地图」类看图题；
- 「四线三格写单词」「填词游戏」「根据音标从方框中选择」等共用格子/方框的题；
- 「用 can/can't/could/couldn't 的适当形式填空」；
- 「填入恰当的特殊疑问词或词组，完成对话」。

**记为 standalone（单独题）**

- 单项填空、完成句子（汉语提示 / 改写句子 / 划线提问 / 同义句转化）、单词拼写（汉语及首字母 /
  适当形式 / 汉语提示 / 词形转换 / 句意及音标中的一句一空题）、翻译、改错、书面表达；
- 一句一空的语法功能词填空（人称代词、do/does、连词 and/but/because、介词、How/What、if/whether、
  关系代词）**暂时**仍按单独题；用户若统一改为组题，只改 `spell-grammar-word` 一条规则。

## 四、版块容器（不单独计数）

| 名称 | 处理 |
|---|---|
| `综合阅读提升` | 版块容器；其后的 `Ⅰ.完形填空`、`Ⅱ.阅读理解` 各自成题 |
| `单元话题写作` | 版块容器；内部通常含 1 道译写小题 + 2 篇书面表达（第一篇带审文导写） |
| `☆拓展设问` | 附在最后一小题后的开放性追问；并入所属组题的第 N 小题，不另立题型、**不计入空数** |

## 五、在代码里怎么用

```python
from workflow import sync_practice

sync_practice.classify("Ⅰ.根据首字母及汉语提示补全单词")
# {'type': '单词拼写', 'subtype': '汉语及首字母', 'kind': 'standalone', ...}

sync_practice.classify_with_body("Ⅳ.阅读理解", body)   # 用正文补 选择3题/4题/5题
sync_practice.audit_units(units, raw_text)             # 结构单元与口径对一遍，只报差异
sync_practice.prompt_block()                           # 给模型看的紧凑版口径
```

命令行自检与单条查询：

```bash
PYTHONPATH=app python3 -m workflow.sync_practice                # 校验规则是否合法
PYTHONPATH=app python3 -m workflow.sync_practice "Ⅱ.完形填空"   # 单条映射
```

## 六、在流程里落到哪

1. **提取与结构候选**：按原生行号识别课时、带序号及无序号作答标题，每处保留 `occurrence`、`start_line/end_line` 和课时上下文。同步材料中基础段/提升段重复大题号不再被误判为答案附录；中段范文不截断后续课时，明确的尾部答案块仍可分离。Markdown 加粗只在识别副本中清理，原文不改。
2. **结构确认（`structure_ai.auto_classify`）**：只在同步材料中追加完整规则条件和大题位置候选；归类完成后按标题归属比对题型、组单及共享材料窗口缺口，差异写入 `01_source/structure.ai.classified.json` 的 `sync_audit`。缓存绑定规则及识别模块摘要，规则变化后不复用旧结论。
3. **前置组装判型**：`preassemble` 使用的题型任务也接收同一规则与标题候选，任务输入摘要绑定规则文件和识别模块。题内的期中/月考等来源标签不能否定同步课时身份。
4. **不影响闸门**：`sync_audit` 只是留痕与提示，结构闸门仍以原卷证据为准；不因口径差异自动改题型、组/单或放行。
5. **题型/子类**：`classify()` 是标题映射，`classify_with_body()` 只在正文证据充分时补子类；例如只有 A–G 七个选项齐全才提示 7选5，任务型没有明确作答证据时不默认阅读问答。

### 单课时来源

后续按一个课时一批次录入。`metadata_ai.identify_source()` 从原件文件名、真实来源路径和独立章节标题识别 `grade/book/textbook_version/series/unit/lesson/section`，生成来源，例如 **七上人教版课时A计划 Unit 1 课时1**。`uint` 规范为 `Unit`，`Starter Unit 1` 与 `Unit 1` 分开。字段证据写在 `source_evidence`，有效非空的既有值保留。

原件名优先读取上传入口保存的原名，不使用批次名猜来源。真实父路径中明确的《课时A计划》可补系列证据；路径已丢失且文件名没有该系列时留空。整册含多个单元/课时，仅生成册级来源（例如“七上人教版课时A计划”），不拿第一课时冒充整册。没有模型配置时也可补齐确定证据字段，不改变阶段完成状态。

### 同课时重复题号与原卷排序

同步练习新结构采用 `identity_version=scoped-v1`。原卷大题的 `Ⅰ、Ⅱ、Ⅲ`、标题、课时上下文、出现序次和来源行号保存在 `source_section`，原样按源顺序展示；基础段与提升段再次出现的 `Ⅰ` 是不同大题。`numbers` 和子题 `number` 保留印刷小题号，不改成全课时连续编号。

`section_id` 标识大题，`unit_id` 标识一道独立题或一个题组，`question_ids[str(number)]` 标识其子题。答案、缺失决策、难度和证据的平面映射使用唯一 question ID；解析、知识点、审核与局部修正使用 unit ID 加本单元原号。ID 由来源位置生成，不取答案或题型；相同来源下调整题型、窗口或组单不会重写子题身份。A/B 两篇各有第1题时，以材料窗口区分；同一窗口真的重复、漏题、跨材料或身份混用仍阻断。

图片整题没有印刷小题号时明确保存 `source_span.number_binding=unnumbered_section`、`printed_numbers=[]`；`numbers=[1]` 只为旧字段契约的内部别名，不显示为原卷第1题。同行多题及 `C:1.` 形式仅在已绑定同步窗口中识别，原文不改。

来源材料必须证明同一大题、出现序次及局部原文坐标。纯数字答案附录没有大题对应证据时，明确报告来源尚未绑定，不选首条、不借同号答案，也不把真实存在但未绑定的内容当作缺失。保留 Word > PDF > 缺失占位顺序；作文不要求客观题答案。预览、编辑保存和原文审计均按唯一身份查找，不能回退到全文第一个同号题。

旧批次没有 `scoped-v1` 时继续旧数字协议，不迁移历史数据。结构失败的旧 provisional 数字兜底不接管 scoped 批次，避免串号。原件回归可定位七上全部305处大题；首课时118行通过结构→草稿→最终原文审计：27个单元、40个印刷小题号和1个无印刷题号内部别名。该确定性回归不替代后续真实模型打标、听力与内容审核。

## 七、扩展方式

新增或修正一条口径：先在 `sync-practice-rules.json` 的 `rules` 里加/改规则（`any` 关键词、
`none` 排除、`subtype_any` 附加条件、`type/subtype/kind`、`note` 写明依据），再跑
`python3 -m workflow.sync_practice` 自检（会校验主类与子类是否属于目录叶子），最后补一条
`app/workflow/test_sync_practice.py` 的用例。

规则顺序即优先级：更具体的规则必须排在更宽泛的规则前面（例如「完成思维导图」必须排在
「任务型阅读」之前，「填词游戏」必须排在「根据首字母…」之前）。

## 八、已知差异（留档，不擅自改）

- 七上已上传批次的旧口径与本表不同：`按照字母表顺序，写出空白处所缺字母`（`RJ7A-U1-01-401`）、
  `判断下列各组字母的大小写是否一致`（`RJ7A-U1-01-403`…`410`，拆 8 条）、
  `在下列四线三格中写出加点字对应的英文单词`（`RJ7A-U2-01-001`…`003`，拆 3 条）当年按单独题录入，
  现口径为组题。历史批次不改写，新批次按本口径。
- 书面表达的子类（列中文要点 / 列思维导图 / 表格 / 图文结合…）由提示形式决定，规则里保持
  `subtype: null`，必须看正文后续内容才能定，不得按标题猜。
