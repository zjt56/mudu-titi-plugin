## 二、硬规则（用户反复强调，必须遵守）

> 本节只写原则；每条规则的落地文件、函数与回归测试见 `app/docs/rules-detail.md`，按规则编号对应。新增或修改规则时两处同步。

1. **零人工本地执行**：全程不得出现人工干预、人工判断、人工选择；不得因"待复核/待核验/人工确认"停住。
2. **卡点必须自愈**：遇到问题由 AI 自行诊断、**实际修复**、复验、续跑；不能只加函数/提示、不能原样重试后停住、不能等用户反复点继续。单点失败不能阻塞无关独立分支；有依赖的下游只能在上游产物完整、格式正确、当前且通过消费者校验后推进。未完成、needs_review、缺失/过期/不合规产物不得视为交付；依赖等待不能伪装成功或质量通过。禁止编造内容蒙混过关。卡点说明必须指明具体检查项与判定口径（哪条检查、为什么判失败、怎么修），不能只写“按阻断项修复”；调度不得仅因 JSON 空白、键顺序或生成时间等序列化差异停住/重跑；模型限流只延后模型调用，不得冻结不依赖该模型的本地命令/闸门或独立分支；精确哈希仍用于任务在途输入绑定、原件/媒体证明与上传冻结，真实内容变化必须通过消费者校验并按影响范围处理。
3. **不自动上传/发布**：`upload_gate / upload / publish_gate` 本地一律 skipped，绝不自动提交题库；远端提交须用户明确授权。**但用户手动点上传时，产物“过期/内容变化”与“未完成审核/有审核差异”都不阻碍上传**（用户已多次强调）；只要本地体检 validate 曾通过即可上传，内容正确性由用户自行把关，标签/结构等硬校验仍在。
4. **原文保真**：题干/选项/材料/表格必须等于原卷切片；Word 与 PDF 同时存在时以 Word 原文为准，PDF OCR 只辅助层级与版面；但当 Word 确实缺少某题解析/答案或某篇文章大意时，可按随附 PDF/OCR 原文兜底并记录来源，两者都没有才留空占位。**同一份卷被重复提取成多份来源时（PDF 附件副本、OCR 副本、materials/*.txt），副本不得参与“唯一绑定”竞争**；`01_source/material-roles.json` 中 `content_authority=false` 的文件只作佐证，不构成冲突。同题、同来源身份内逐字相同、仅位置不同的重复原文按内容等价验收，引用仍须命中真实坐标；不得仅因锚点数大于一误判冲突，也不得借同文跨大题绑定。权威来源内部同一题出现两份不同解析，仍必须判为冲突。
5. **空白语义**：未判定字段留空；确认原内容不存在时保留既有占位（无解析/未填写/未提供），不得一律清空。
6. **审核范围**：人工审核只收两类差异——知识点标签差异、基本差异（题型/子类/答案/解析/原文）；难度/来源/分类/选题/词数不进审核、不比对、不显示。图片/音频能力受限只作 informational，不进人工队列、不阻断；此豁免只针对能力限制本身，**程序已比较出的真实标签差异不得因审核理由提及图片/音频而被过滤**。**当前审核为一审＋标签合并，历史二审及其未裁决差异保留兼容**。一审或历史二审与原标签不一致，必须进待审核；不得以“审核判断与当前正式标签不同”为由把差异当过期结论丢弃。**盲审隐藏标签不等于正式标签缺失**：一审及历史二审记录只独立填写 assessment，由程序比较原标签；把刻意隐藏字段当缺失的结论必须自动补审，不得误入人工队列，也不得直接伪改为通过。标签一致时仍须保留真实答案/解析/原文错误。**技术性变化不得清掉未裁决差异**：来源/年份等题目来源元数据的清理不参与审核语义绑定（真实 `evidence.source` 仍参与）；因输入绑定升级而退休、内容可证明等价的未裁决差异必须放回活动队列，保留原判据、换新 `finding_id` 并幂等去重，不能因为一条技术性绑定变化就让真实差异无声消失。**差异是产出，不是卡点**：一审或历史二审与原标签不一致的条目必须完整留在 `07_review/manual-review-queue.json` 与 `review-gate.json` 的 `rounds.errors`，供工作台人工判断（用来发现模型/知识头的偏差）；禁止自动 resolve、禁止为放行改判通过或改标签；`review_gate=needs_review` 就是该设计状态，不得当成故障“修复”，也不阻断用户手动上传（规则 3）。**卡点诊断与运维自愈同样适用**：`review_gate=needs_review + execution_completed + continue_unqualified` 显示为“差异待人工判断”（`failure_class=quality_differences`），不计入“需处理”，也不得触发改标签/局部重生成；只有 `blocked` 的确定性阻断项才算卡点。 落地见 `app/docs/rules-detail.md` 规则 6。
7. **流程图固定 12 类**：内容提取、结构确认、组装判型、听力处理、答案填充、解析填充、知识标注、汇总整理、本地体检、内容审核、格式检查、审核上传。主图只显示分类，全部子流程及真实状态仅在悬浮文字层呈现，不常驻展开。箭头必须表达真实依赖，不能把并行分支画成串行；有实际工作才显示处理中，不能仅因依赖满足或旧文件存在而伪造子流程完成。
8. **模型不固定在仓库，也不静默兜底**：仓库 `config/model-router.json` 的 `default` 保持为空，每台设备自动跟随自己 Harness 当前选中的模型（`agent-default-model`），也可在插件设置里显式指定。显式配置的 provider/model 一定被严格使用；配置存在但损坏/不完整时必须报错，绝不静默换成其他模型。
9. **质量≠执行**："已执行，有差异"不等于通过；`review_gate` 不得因此放行；`release_ready` 只有在真实审核后才可能为真。
    **答案格式容错**：答案填充与下游比对使用同一归一化口径；加粗/画线标记、空白换行、直弯引号、全半角符号、备选分隔旁空格和句末句号不影响答案正确性时，不得造成失败、重跑或人工判断。保留原始答案，不擅改词句；数字、小数点、正负号、否定词、选项和实质内容变化仍校验。
    **统一问题闭环与检查时机**：所有确定性检查保留完整结构化证据并复用现有自愈/运维入口，不另建重复修复队列；警告与审核差异不触发内容重生成。前期只拦截会破坏来源、身份、归属及消费者交付的实质错误；内容完整性（contentComplete）、难度一致性与重复显示检查后移最终闸门，难度硬约束仍须执行；类型/前置组装遇到内容未确认时保留候选与 `contentComplete=false`，不得提前阻断，也不得伪造为 true。元数据/画线的来源投影不得要求尚未交付的答案解析和标签；最终组装交付后须同步后续实际消费的最终产物。独立分支继续推进，未合格输入不能伪装完成或被依赖方消费。最终集中复用来源/原答案解析严格核对；独立原件整页覆盖和浏览器渲染未检查时必须明确标注，不能宣称全链路完成。 落地见 `app/docs/rules-detail.md` 规则 9。
    **格式小问题不阻断流程**：标点、全角空格、连续下划线/答题线占位、`<br>`、首字母与空档间距、表格列数/空档写法等格式表达问题只作 `[W…` 提示，不阻断 validate；只有题目/题干/题号对不上、答案或来源不符、结构错位这类实质错误才阻断。 落地见 `app/docs/rules-detail.md` 规则 9。
    **原卷合法空/图形态不算内容缺失**：结构确认、前置组装（含题型）、体检等任一环节都不得把以下三类当成题目内容缺失而阻断——①纯图片题（除 `[IMG …]`/`[TABLE …]` 外无可读文字题干）；②空白作答网格（表格全空、答案在卷末附录可按题号对上）；③整节无印刷小题号也无图片但有正文（如字母歌补全、熟词生义）。无号文字作答题按通用来源规则处理，不限栏目名称：须证明当前大题窗口、可读正文与明确作答区域；连续独立作答行各建单元，自然换行仅在唯一末尾作答区域及连续正文可证明时保留整窗；候选须逐窗完整覆盖，不得漏题或合并多题。栏目只按印刷文本标题识别（视觉理解已停用，见规则 34），普通文字须有明确栏目包装或既有标记；栏目只辅助边界，不决定题型/题数/答案且不混入 A/B 板块。内部别名不得变成印刷题号，上传范围须由来源证明投影为 `null/null`；空白行、边界歧义、多题混窗、真实题干截断仍拒绝。判定缺失前必须先排除这三类，`contentComplete=false` 的数智判定只能基于真实截断/缺选项/题干错配并说明缺了什么文字。统一分类函数 `app/workflow/question_content.py::legitimate_source_shape`（布尔封装 `capability_limited_source`），结构闸门与前置组装共用同一口径，不得各处各写一套。 落地见 `app/docs/rules-detail.md` 规则 9。
    **编号空格/空位号不是印刷题号、也不是漏题**：完形/短文填空材料行内的 `<u>　n　</u>`（含 `</u>.` 后句点）、补全对话/信息转换的 `N.　　`/`Xxx.N.____` 空位写法都是子题号本体；结构锚点必须先按库侧空档写法 `normalize_blank_text` 规范化再识别，`_weak_numbers` 也要认“题号在空位前”的对话空位。不得把编号空格误当与下方 `( )n.` 选项并列的重复锚点（否则误报 SOURCE_DUPLICATE_NUMBERS/QUESTION_NOT_FOUND），也不得因 `N.` 紧跟文本句点而定位不到空位。 落地见 `app/docs/rules-detail.md` 规则 9。
10. **不动用户数据**：不重跑/改写已归档批次；不直接编辑 `workflow/manifest.json` 造完成态；不自动删除用户试卷。
11. **卡点必须指明批次**：任何卡点、待复核、失败或“继续处理”错误，必须同时显示具体批次名称和可定位的批次目录；收到泛化错误反馈时不得猜测或拉起其他批次。
12. **原卷预览图片显示**：表格单元格里的图片必须与该单元格文字在同一单元格内显示，不得拆到单独的行尾/额外单元格；表格必须自适应容器宽度并自动断行（`width:100%`、`table-layout:fixed`、`word-break:break-word`），不得因内容撑宽导致左右滑动；原图（尤其表格内图）缩得很小（表格内缩略图约 36×28，正文图 `max-width:200px`）。只影响预览渲染，不改题目数据。 落地见 `app/docs/rules-detail.md` 规则 12。
13. **题组材料必须在题号前完整绑定**：group（题组）从原卷绑定来源时，必须使用**完整 confirmed span 窗口（文章/表格/导语 + 题目）**；定位 stem 只能证明其在窗内，绝不得据此从首个题号起截取、把题号前的材料丢掉（否则 group 的 `material` 为空、装配报 A8）。`source_span.basis` 为 `ai_classified` 或 `cleaned_source` 均属可信边界；standalone 仍只绑定自身题干。表格材料用 `[TABLE ...]` 原样保留。 落地见 `app/docs/rules-detail.md` 规则 13。
    **共享材料按原卷证据判缺与修复**：适用于各题型的题组。按当前确认的完整来源窗口核对本组所需的文字、表格、图片或音频，以及作答导语和成员小题。仅在原卷和题型契约证明本组无需文字材料，其余必需内容均已交付时，`material` 才可为空。附件须验来源、文件和层级归属，子题图、装饰图或其他题组的附件不得顶替共享图。发现遗漏或错绑时，从原卷追到首个丢失或覆盖的阶段，仅对可唯一绑定的单元恢复原文或原生结构，经既有交付入口同步下游。旧快照不得覆盖已核实内容。证据缺失、歧义或冲突时，记录批次、单元、检查码和具体缺项，保留候选并按现有运维入口升级，同证据不得原样重试。修复须复验原失败检查、最终交付、预览及上传映射，并覆盖合法空字段、真实缺失或错绑、旧快照覆盖和重复续跑。禁止按批次、题号或文件名写特判，禁止填占位凑通过。

14. **预览不得丢题组材料**：已验证 scoped 来源窗口中的题组图片（含纯图组题、首个印刷题号前的材料图）优先于页眉位置/宽高比启发式，不能误删；显式排除仍优先，过期或冲突来源不能提升。原卷预览按题号切出的片段必须包含题号之前的共享材料（文章、`[TABLE N]` 表格、`※Notes` 备注、分段 A/B 标签）；预览切片不得因“段落标签/弱题号”把表格或正文截掉，也不得把材料排到题目之后。只影响预览与只读核对，不改题目数据。 落地见 `app/docs/rules-detail.md` 规则 14。
    **数据完整 ≠ 展示完整**：修复“内容丢失”类问题必须同时验证①批次数据字段、②每一层消费/展示输出（预览切片、`source_blocks`、payload），只验证一层不算通过；并且必须补一条覆盖该链路的回归测试，避免同类问题再次漏检。
    **共用大题题干不得只挂在第一组**：完形 A/B、阅读各篇共用同一大题的作答导语；后一组来源窗口只含自己的文章时，必须依据已验证来源坐标补回同节标题之后、首篇材料之前的完整公共导语；含限定题号的组内导语不得传播，本组专属导语优先。生成、原文审计和预览使用同一归属规则，保留 `A`/`B` 分段标签与材料原文，禁止留空或编造；`第一节`/`第二节` 分段前缀只用于识别匹配。 落地见 `app/docs/rules-detail.md` 规则 14。

15. **听力并行、非听力内容审核不等待听力（2026-11-21 用户确认方案 A）**：听力（audio）切段/转写耗时最长，不得阻塞答案、题型、解析、知识点、组装（assemble）、本地体检（validate）以及**非听力内容审核分片**。`review.depends_on` 为 `("validate",)`，当 `validate` 通过后，全部非听力 `review` 分片立即与 `audio` 并行执行并写入独立于音频指纹的缓存（`workflow/review-pending/nl-*.json`）；仅含听力题的审核分片等待 `audio` 交付转写后补跑（届时非听力分片零模型复用），`format_gate.depends_on` 显式包含 `("review_gate", "audio")` 以确保最终打包前音频切片完整合入。 落地见 `app/docs/rules-detail.md` 规则 15。

16. **Word 表格空白网格位置不得丢失**：转换表格时必须保留 `grid_before/grid_after` 明确记录的行首/行尾空白列，以空单元格表达，保持非空文字及 `rowspan/colspan` 不变；禁止为凑齐行宽猜改合并跨度。存量表格只在原件摘要匹配、源表唯一绑定、旧投影逐项相等时，通过有备份的事务恢复并复验；无证据的结构错误仍须如实报告。 落地见 `app/docs/rules-detail.md` 规则 16。
17. **格式诊断必须区分失败与延期检查**：最终上传格式检查优先读取 `07_review/upload-format.json.errors`，显示错误码、题组标识和具体原因；`deferred/warnings` 不得冒充本地阻断。报告缺损时回退日志中的结构化错误，不能从末尾抓一句“必须”当失败原因。知识点目录快照/媒体部署等延期项仍须在真实上传准备时检查，不得为修本地卡点放宽远端校验。 落地见 `app/docs/rules-detail.md` 规则 17。
