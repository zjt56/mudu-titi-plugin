## 叶子与名称

当前本地索引以“没有更长目录路径以自身加 `/` 为前缀”的节点识别叶子。存储完整目录路径，通过目录取名称和 ID；不要自行拆路径最后一段当名称。

| 情况 | 处理 |
| --- | --- |
| 命中目录叶子，如 `词汇/词汇辨析/名词辨析` | 使用目录给出的路径、完整名称和 ID |
| 命中父节点，如 `主题/人与社会` | 不作为独立知识点提交 |
| 维度根节点，如 `主题`、`语法`、`语篇体裁` | 不作为标签提交 |
| 路径不存在 | 纠正候选，不能自行创建节点 |
| 名称含 `/`，如 `谚语/习语`、`固定搭配/句型`、`what/which` | 保留原名；`谚语/习语` 的完整路径是 `语用/谚语/习语`，不能改成顿号 |

原文“体裁/词汇/语法/语音写根以下各级”解释为界面可显示祖先链，实际标签仍只存命中叶子；主题同样只存叶子，不把一级主题重复提交。阅读和听力中的同名角度必须按 `设题角度/阅读/*` 与 `设题角度/听力/*` 区分，不能只凭“细节理解”匹配。

## 按题型的维度范围

下表表示允许范围，不要求每题把整行所有维度都凑齐。先识别实际考查内容，再按题组/子题层级落标；明确必带项见下节。

| 题型 | 允许维度及范围 |
| --- | --- |
| 听力短对话理解、听力长对话理解 | 主题、设题角度〔听力〕 |
| 听力短文理解、听力判断、听力排序、听力问答、听力其他 | 体裁、主题、设题角度〔听力〕 |
| 听力信息转换 | 体裁、主题、设题角度〔听力〕；对应空按实际答案考点 |
| 听力关键词语选择 | 语音、词汇、答案考点；无设题角度 |
| 语音题 | 语音 |
| 单项填空 | 词汇、语法、语音、语用、答案考点 |
| 完形填空、语法选择 | 题组仅体裁、主题；子题按实际词汇/语法考点 |
| 阅读理解、任务型阅读、读写综合 | 体裁、主题、设题角度〔阅读〕 |
| 教材语篇填空、短文填空、选词填空 | 体裁、主题、词汇、语法、答案考点 |
| 补全对话 | 体裁、主题、语用 |
| 单词拼写 | 词汇、语法、语音、答案考点 |
| 完成句子 | 词汇、语法、答案考点 |
| 情景运用、翻译 | 词汇、语法、语用 |
| 改错 | 词汇、语法 |
| 书面表达 | 体裁、主题 |
| 其他 | 按材料的体裁、主题、词汇、语法、语音、语用及答案考点；阅读任务使用设题角度〔阅读〕 |

“其他”在固定机器表仍残留“阅读技能”旧字段；本次按打标说明迁移到 `设题角度/阅读/*`，不把不存在的旧根节点提交。

答案考点不是第八个维度，而是本题/本空实际考到的词汇或语法叶子。需要变形才加相应语法，派生才加构词法，不据题型机械添加。不得给完形/语法选择题组另加答案考点；语法选择也不再要求组级“必须有一个语法点”。原打标说明只明确举子题词汇，实际语法考点可写对应子题是本次明确决定，不冒充原文逐字结论。

## 题组与子题分别落标

标签按层级保存。题组共同材料属性在组级改一次，子题保留自己的角度或考点；“组级改一次”不表示子题标签全部为空，也不表示无条件复制整组标签。

| 题型家族 | 题组级 | 子题级 |
| --- | --- | --- |
| 阅读 / 任务型 / 读写综合 | 必有体裁＋主题；可汇总组内全部实际阅读角度 | 每道子题必有对应阅读角度，不复制体裁 |
| 完形 / 语法选择 | 必有体裁＋主题；无词汇、语法、答案考点或设题角度 | 按该空实际词汇/语法考点落叶子，不照抄组级材料属性 |
| 选词 / 短文 / 教材语篇填空 | 必有体裁＋主题；词汇/语法按实际考点 | 对应空有独立考点时记录；不得把界面隐藏空壳列表误当成删除子题考点 |
| 听力长对话 | 必有主题；汇总组内实际听力角度 | 各自听力角度 |
| 听力短文 / 信息转换 | 必有体裁＋主题；汇总实际听力角度 | 各自角度；信息转换答案考点按实际空位处理 |
| 补全对话 | 体裁＋主题及实际语用 | 按具体作答形式处理，不无条件复制整组标签 |
| 单词拼写 / 完成句子 / 语音题 | 通常逐题；共享材料是否成组按原卷结构决定 | 各题实际词汇/语法/语音考点，受本题型范围限制 |

历史实现曾用以下单元候选表达继承：

```json
{
  "applies_to": "unit",
  "numbers": [16, 17],
  "inherit_subquestions": true,
  "labels": { "knowledge": ["..."] }
}
```

该字段不能作为跨层复制许可。装配需按题型筛选可继承内容，并保留子题已有的实际考点；空壳子题是否显示属于呈现规则，不改变数据层的子题标注责任。

## 数量建议与检查强度

原文“1–3”“通常 2–4”是不同历史精简建议，“同维度最多一个”也不能直接用于所有层级。组级汇总可能有多个设题角度；每个子题仅写自己实际角度/考点；多主题需有材料依据。最终检查应判断路径、叶子、层级、允许 scope、必带项及真实考点，不以标签总数或同维度条数直接拒绝。

技能侧历史 `check_tags.py` 说明为空标签/非叶子/旧禁标失败、普通越界仅报告，`--strict` 才失败。这是来源行为记录，不意味着本地已完成等价检查，也不能代替本地最终严格门槛。

## 已实现的共用校验与审核闸门

[workbench/taxonomy.py](../workbench/taxonomy.py) 是本地共用校验入口：

| API | 实际职责 |
| --- | --- |
| `resolve_knowledge` | 返回命中的叶子、未知路径与父节点，并从目录保留完整名称/ID |
| `check_labels` | 部分草稿校验：可缺主类、子类、知识点；已填字段须合法，列表字段为字符串列表，只有单词拼写允许多个子类；按已填主类检查维度/scope |
| `check_unit_dims` | 动态读取全部 27 类 `by_type.dims`，检查组级允许范围、听力/阅读 scope 及必带材料维度；完形/语法选择组级禁词汇、语法、设题角度 |
| `check_question_labels` | 最终单元及子题递归校验：主类、适用子类、非空知识点、目录叶子、维度/scope、组级必带项、子题规则，以及提供了 ID 时的路径/ID 集合一致性 |

最终校验时，未显式填题型的子题只继承父题型用于选择规则，不继承父题知识点或子类。完形/语法选择子题限制在词汇/语法；阅读子题必须有阅读角度且不能挂体裁。校验不设标签数量硬上限，也不修改输入。这些是目录与结构检查；考点在语义上是否符合原题仍需内容复核，不能据校验通过宣称语义已自动验证。

[workflow/label_audit.py](../workflow/label_audit.py) 提供 `inspect_batch`、`inspect_file`，与审核台复用上述校验，可直接只读检查最终批次：

```bash
python -m workflow.label_audit --batch path/to/batch_meta.json
```

命令输出 JSON，成功退出 0，失败退出 1。每条标签问题以 `LABEL_RULE_VIOLATION` 携带单元 ID、条目索引和子题定位文案；无效批次或不可读文件另报结构化错误。成功读取文件后的结果包含批次 SHA-256 和题型框架、知识点目录、维度表三份目录的 SHA-256，便于识别本次实际检查的内容。

[workflow/checks.py](../workflow/checks.py) 已把该模块登记为第 17 项本地体检，使用本仓库内置模块执行；外部发布侧 `check_tags` 仍是另一项检查，缺脚本不能算通过。[workflow/runner.py](../workflow/runner.py) 的 `do_review_gate` 在放行时重新读取实际 `06_batch/batch_meta.json`，把审计结果写入 `label_audit` 并合并错误；标签不通过就阻断审核闸门，不仅依赖旧审核结果。该接入位于 runner 闸门，不能据此宣称 `review.evaluate` 本身直接调用了标签审计。

[workbench/server.py](../workbench/server.py) 的候选保存允许部分标签，使用共用校验返回可见 `labelWarnings`，便于持续编辑；清空知识点路径时同步清除旧 `knowledgeIds`，避免残留旧关联。**草稿保存成功不代表最终放行**：最终批次仍须通过上面的严格校验，不能用无条件继承或静默抹掉非法标签绕过规则。
