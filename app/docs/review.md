# AI 审核、二审与人工队列

用户要求的顺序是：先完成最终格式装配 → 本地 AI 审核 → 一审全量独立盲判标签 → 二审按 20% 独立抽样核对知识点与题目的语义对应（整组题型整组抽取、只做组级核对）→ 处理真实发现 → 审核闸门。没有发现的题不需要人工逐题确认，不要求人工姓名、签名或密钥。

## 人工审核范围（产品规则，2026-11）

插件目的是「拆卷 → AI 打标签 → **只把有差异的题挑出来人工审** → 批量入库」，不做全文重审。因此人工审核队列与审核闸门只收两类差异：

1. **知识点标签差异**：同一题/题组的「原标签 / 一审 / 二审」判出的知识点不同（含主题、设题角度、语篇体裁等目录叶子路径不一致）。
2. **基本差异**：题型/子类等基础标签与当前标注不同，或答案、解析、题面与原文不符等实质差异。

以下**不属于**人工审核范畴，只作为 `informational` 提示保留，**不进人工队列、不阻断审核闸门**：

- 因 AI **看不了图 / 听不到音频**导致的“图片占位、无法确认图文对应、无法核对配图”等不确定。这是模型能力边界，不是标签分歧，逐条人工看图只会拖慢效率。**此豁免仅适用于能力限制本身**：程序已按结构化 type/subtypes/knowledge 值比较出的真实差异，不能因某轮理由提及图片或音频而降为 informational；无论该轮 verdict 为 ok、error 还是 uncertain，真实差异均保留待审。
- 正常一致（原标签=一审=二审）、逐题确认、无害转写差异、以及“无需处理”的结论。

**审核范畴与说明精简（用户 2026-11）**：人工审核**只审「知识点标签」**——难度、来源、分类、选题、词数等基本标签**不进入审核、不参与比对**，审核面板也不展示它们。`review_consensus.compare` 不再产出 difficulty 类差异（难度以首次打标签结果为准，一审/二审难度判断不作为人工审核发现）。「审核说明」**越短越好**：只在有知识点/题型差异时给一句原因（差异原因：…），不罗列原文核对。

**界面呈现规则（用户 2026-11）**：右侧审核面板主区域**只展示「知识点标签」三列差异**（原标签 / 一审 / 二审）。题型、难度、来源、分类、选题、词数等其它差异与说明，**统一放在下方「审核说明」文字里**，不要再单独另开一个框/卡片，也不要把难度做一审/二审比对（难度以首次打标签结果为准）。

**知识点差异判定（用户 2026-11 修正）**：知识点是否"不一致"按**完整路径集合是否完全相同**判定——只要原标签 / 一审 / 二审任一方与原标签的路径集合不完全相同（包括打在不同维度根上，如 `语法/副词/…` vs `词汇/词汇辨析/…`；也包括多打或少打一个维度，如多出 `语音/基本读音/…`），都算差异，必须进人工审核。此前"不同维度根互不相交不算冲突"的宽松规则会漏掉真实分歧（例如第 40 题 原「频度副词」vs 一审「副词辨析」），已废弃。

实现：`workflow.review.MANUAL_REVIEW_SCOPE = "label_and_basic_differences_only"`；`review.evaluate_rounds` 用 `_is_capability_gap` 把能力受限的 `uncertain`/`REVIEW_SAMPLE_SOURCE_UNVERIFIED` 归入 `informational`，不作为 `REVIEW_ROUND_FINDING`、不列入 required unchecked。涉及具体标签/答案冲突的 `error`/`uncertain` 仍照常送审。

## 现有接口的能力边界

`workflow.agent_tasks` 的 `review` 任务是 **一次本地 AI 审核**。旧产物 `07_review/agent-review.json` 的 `checked_units` 仅说明该任务声称检查的单元；不能据此推导一审、二审、二审已完成。导入兼容旧协议，但会把缺少的分轮审核保留在 `07_review/unchecked.json`，正式闸门仍阻断。

非空、结构覆盖、目录值合法、知识点 ID 对应等程序检查是确定性校验。它们不能判断“这个空是否考这个知识点”，不能重复运行三次后宣称三次独立语义审核通过。机器也无法凭 JSON 证明审核者真正阅读过题目；下面的协议验证输入绑定、记录完整性和证据可追溯性，语义质量依赖真实执行的审核。

## 分轮记录协议

新增产物为 `07_review/review-rounds.json`，形状为 `{ "plan": {...}, "rounds": [...] }`。计划由可信编排器调用 `workflow.review.prepare_round_plan(batch_dir)` 生成；模型不得自造摘要或改写计划。计划不包含任何已审结论。

计划包含 `protocol=upload-workflow.review-rounds/v3`、`input_binding`、`input_hashes`、单元清单 `units`、完整小题清单 `questions`、样本清单 `sample` 和 `sample_method`。绑定覆盖原卷文字、确认结构、类型、知识点、最终批次、存在的答案/提取/音频证据，以及目录和匹配规则。在途任务仍以原始字节绑定，输入变化后必须重新导出；已经真实完成的结论则按 `unit_bindings` 检查，只对实际变化的单题或题组补审，不能仅因其他题或来源元数据变化而整轮重跑。外部图片或音频未核验时仍须记录不确定，文本摘要不能证明看图或听音。

审核分两轮，减少一次全量模型调用：

- `labels`（一审）：覆盖所有确认单元，一次判完题型、子类、组级知识点（整组题型不判子题知识点）。
- `sample`（二审）：只覆盖按可复算规则抽中的 20% 目标，整组题型整组抽取、只做组级核对，复核题面、答案、标签与原文的对应。

每轮必须来自实际的不同执行，并包含：

- `round_id`：`labels`（一审）、`sample`（二审）。
- `input_binding`：原样返回计划的绑定值。
- `execution_id`：真实调用/任务 ID，两轮不能相同；它不是人名或签名，也不能证明独立判断质量。
- `checks`：实际逐单元或逐样本的结论，不能从程序校验结果自动填 `ok`。

每条 check 必须包含 `unit_id`、`verdict`（`ok` / `error` / `uncertain`）、解释判断依据的 `rationale`、`evidence` 和该轮专用 `assessment`。二审的 check 在目标是独立单题时带字符串 `number`，必须与抽中的题号一致；目标是整组题型时省略 `number`，只做组级核对、不拆小题。

非 `ok` 的明确问题可选填 `issue_key`（具体问题）及 `resolution_key`（包含目标和预期结果的具体处理动作）。只有实质相同的处理动作才能使用相同的 `resolution_key`；不确定时省略。跨轮合并还要求问题、处理动作、目标、输入绑定、判断、理由和证据完全一致，且原发现和人工队列均未关闭；完整各轮 assessment 均保留在 `round_sources`。缺少这些键的旧记录不会据此合并，新来源不会继承已有的关闭决定。程序只能比较文字，不能证明不同 assessment 在语义上或处理诉求上确实一致；一个合并后的人工决定会覆盖其所有来源，审核时必须逐一核对。

证据是非空列表，每项 `{ "path": "01_source/正文.txt", "locator": "第1题/相关句", "quote": "原文真实片段" }`。路径必须在当前绑定输入中，quote 必须真实存在；每条 check 至少引用一条原卷文字证据。只引用目录、复述“非空/目录合法”，不构成语义审核。未经读取的图片、音频不允许编造原文片段或核验声明。

### 一审：重新判断标签

`labels` 精确覆盖所有确认单元，每单元一条。**盲判**：轮次上下文不含任何现成标签（题型、子类、知识点、难度都不给），只给原卷题干、材料、选项、答案与解析；审核者独立推导主类和子类，判出组级知识点（整组题型只判组级，子题 `knowledge=[]`；独立单题判自身知识点），并由程序把盲判结果与当前标注比对。`assessment` 为 `{ "type": ..., "subtypes": [...], "knowledge": [...], "subquestions": [...] }`。知识点路径必须逐字取自供给目录，不得自造更深的子级；答案或内容的冲突用 `error` / `uncertain` 加依据指出。真实差异或不确定进人工队列。

### 盲审视图与缺失判断（2026-11-08）

两轮供给的批次都是刻意去标签的视图：`type/question_type`、`subtypes`、`knowledge`、知识点 ID 与 `filterMetadata` 不对审核模型公开。模型只独立填写 `assessment`，由程序与原标签做完整集合比较；不能要求模型引用被隐藏的当前标签，也不能因视图中未提供这些字段而报“标签缺失”。

`review-prompt-v10` 明示此契约。返回的非 `ok` 判断若仍以隐藏标签缺失为依据，校验报 `BLIND_LABEL_ABSENCE`，通过已有目标级修复路径要求重新判断，不将其自动改成 `ok`、不直接删除问题。原响应与证据保留；与原标签一致但有真实答案、原文或解析错误的结论照常进队列，标签集合不同也仍由程序生成差异。提示版本进入分片缓存与逐单元绑定，旧矛盾提示的结果不能作为新版本的已审结论复用；已有队列需在新审核完成后通过 `reconcile_rounds=True` 重投影，保留人工决定和退役记录。

### 二审：20% 抽样

抽样分母按题：整组题型（完形填空、语法选择、阅读理解、任务型阅读、读写综合、补全对话、听力信息转换、选词填空、短文填空、教材语篇填空、听力短文理解、听力长对话理解）整组算一个抽样单位，`number=null`；独立单题每个题号算一个。样本量为 `ceil(抽样单位数/5)`。计划按稳定的抽样单元拓扑和 `{unit_id, number}` 的 SHA-256 排序，取前 N 个；题号与分组不变时，修改题文或元数据不改变抽样清单，模型不能自行挑方便的题。此方法是可复算的固定样本，不宣称秘密随机或统计代表性。

`sample` 精确覆盖该样本，不得遗漏、重复或换题；整组题型不得拆成逐小题 check，也不得对子题做二审。整组题型的 `assessment` 含 `source_comparison`（整组题面、选项、答案、组级标签与原文的核对结论）和组级 `type`/`subtypes`/`knowledge`；独立单题按抽中的小题核对。未抽中的目标没有二审结论，不能称全卷二审逐题通过；全部两轮完成才计 execution_completed。

## 导入与闸门

`workflow.review.evaluate_rounds(batch_dir, payload=None)` 校验当前输入与记录，默认读新增产物；返回 `passed`、`errors`、`unchecked`、`findings`、`checked_rounds` 和当前计划。缺文件、缺轮次、错误抽样、重复执行 ID、过期绑定、缺证据都保留 required unchecked。函数不会生成审核证据或已审数据。

可信编排器收集三份真实结果后，可通过 `workflow.ingest.build_review_files(batch_dir, {"review_rounds": payload, "findings": [...]})` 保存记录、合并发现并更新 unchecked。无效或不完整提交会被拒绝，不能因此清除原有待核验项；完整记录中的 error/uncertain 进入人工队列。旧的 `annotations` 导入计数只记为 `observations`，不再递增“独立审核次数”。

`workflow.review.evaluate` 将分轮校验纳入闸门，同时要求没有未处理的阻断发现、没有未处理人工队列项、没有其他 required unchecked，并保留已有审核文件检查。空 findings/空人工队列是正常的无问题结果，不能为了消除空文件提示制造每题确认项。

真实执行入口是 `python -m workflow.review_rounds run --batch-dir <batch>`。有本机 Agent 配置时，每轮通过 `local_agent.invoke` 启动一个全新实际进程；程序生成 execution_id，模型只回该轮 checks。无配置时只导出当前轮，目录含 README、task、schema、示例四份公开文件；用 `python -m workflow.review_rounds import --batch-dir <batch> --task-id <ID> --result <result.json>` 交回，再 export/run 下一轮。`export` 可显式逐轮文件交接。任务/输入/此前轮次变化时拒绝旧结果；同一任务重复交回相同结果返回原回执，不同结果拒绝覆盖，needs_review 也需重新导出后重试。原始候选、失败和历史记录均保留。文件交接默认完整上下文预算 600000 字符，可用 export 的 `--max-input-chars` 调整；自动调用沿用本机配置的 `max_input_chars`，超过预算直接报错，不截断原文。单题的 error/uncertain 和已有人工队列不会中断后续独立轮次；所有轮次均尝试执行，实际发现保留人工未决。自动执行默认每轮最多尝试 3 次，失败候选与错误记录保留；本轮仍无法完成时继续尝试其他轮次，该轮保持 unchecked，不计作执行完成。缺失安全输入、非法任务绑定或输入变化仍阻断相应执行；修复输入后重新绑定重审。不会跳过冲突单元再把缺项当全覆盖通过。两轮都有合法完整记录时 execution_completed=true；quality_passed 单独表示审核质量结果，有真实发现时仍可为 false。整卷结果写入 `07_review/overall-review-report.json` 与 `07_review/overall-review-report.md`，分别报告审核执行完成、质量通过和人工未决，不能将“流程执行完毕”描述为“质量通过”。

通用 `workflow.agent run` / `import` 已在单次 AI 审核完成后接入上述分轮入口；后续 `next` / `run` 可在同一输入上继续未完轮次。分轮未完时阶段保持 needs_review，不能靠单次 local report 的 completed 宣称全流程完成。单次 AI 初审返回 needs_review 时，若已有通过候选形状与发现证据校验的可读候选或真实 finding，且安全输入与上游条件齐备，入口仍继续独立分轮审核；初审候选保留在 workflow 内部，初审未决保留 required unchecked，不将其伪造为已完成初审。初审与两轮都完成时 review 阶段登记执行完成，质量与人工未决交由整体报告和 review_gate 判断；仅两轮完成而初审尚未完成时，入口仍返回 needs_review，并显式输出 ai_review_completed=false 与 execution_completed=true。runner/contracts 已将新增分轮文件列入审核产物并保留输入失效传播，正式闸门调用当前 `review.evaluate`；全部完成时记录完整审核产物哈希。旧单次 review 阶段完成不代表整个二审完成。部署者如另行显式启用 legacy `independent_review.py` 的 HMAC 配置，仍可额外验签；那是防篡改附加机制，不是用户要求的人工姓名/签名，也不能替代语义复核。

### 容错与重试（2026-11 更新）

- **目标级容错**：分片校验逐条进行；某条引文/字段不合格时保留其余已通过的结果，只把出错的目标写入 `workflow/review-partial/<task_id>.json`，并对这些目标发起一次**局部补审**（提示只含失败目标及其原文、答案、相关转写窗口，约 20–30K 字符），补审结果与已通过结果合并后再导入。整片不再因为一条坏引文而重发 30 万字符的提示。
- **近逐字引文自动定位**：引文与原文的相似度 ≥ 92% 且能定位到唯一原文行时，自动替换为原文精确片段，并保留 `model_quote` 与 `normalized=true` 供审计；转述式引用仍判失败，交局部补审。
- **提示版本进入分片缓存键**：`CONTEXT_VERSION` 与 `PROMPT_VERSION` 变化时分片状态自动失效，不会复用旧版更大的提示。
- **重试预算**：同一轮最多重试 `review_max_attempts` 次（默认 1），重试前指数退避；仍失败则保留 unchecked 并继续其他轮次。
- **打标签并行**：`workflow.runner run` 在 `explanations` 与 `knowledge` 同时就绪时调用并行调度，两路标签一起产生。

### 分片预绑定与并发（2026-11 更新）

盲审上下文版本为 `blind-context-v11`（v9 起二审对整组题型按整组抽取、只做组级核对）；`v1`–`v7` 只作为历史保留，不能导入为新结果。每轮导出时一次性为该轮全部分片生成固定任务与绑定（`frozen_state`），因此分片可以独立执行、不必等待前一分片结果；导入仍按分片顺序进行，每个分片都必须对得上自己的任务、绑定、原始响应与安装事务。

`run` 默认按本机配置的 `part_concurrency`（或显式 `review_part_parallel`，上限 4）并发调用同一轮的多个分片。成功的分片响应先写入 `workflow/review-pending/<task_id>.json`，再按顺序导入；某分片失败时，后续已成功的响应不会丢弃，下一次运行直接复用而不再调用模型。失效或被篡改的轮次（例如证据被改动）会换发新的任务标识，不会被旧回执永久卡住。

两轮统一为同一套结构化判断：`assessment` 含 `type`、`subtypes`、组级 `knowledge`、`subquestions`（整篇题组的子题允许 `knowledge=[]`）；难度不要求生成、不参与比对，旧响应若带该字段仍校验其格式。二审另含 `source_comparison`。程序按 `(unit_id, 字段)` 与 `(unit_id, number, 字段)` 逐项比较原标注与各轮盲判（整组题型只比组级，子题知识点不参与），只把真实分歧、错误或 `uncertain` 送入人工队列；`uncertain` 允许 `assessment=null`，其他目标与后续轮次继续。二审的每个抽样目标还需可核验的原文引证：引文必须精确且唯一地落在目标小题的题干区间（允许空白/下划线标记差异），或落在**同一题组自己的材料行区间**（阅读/完形/任务型阅读的支撑句本就在共享材料里，但绝不接受别组材料）；两者都不满足则保留未核验而不阻断其他题。整组题型（阅读理解、任务型阅读、完形填空、语法选择、补全对话、听力信息转换、读写综合、选词/短文/教材语篇填空、听力短文理解、听力长对话理解）只在组级判定知识点，子题 `knowledge=[]`，不逐小题评估、不做小题二审。知识点目录按原卷大题标题推导的题型范围裁剪（`workflow.review_paper_scope`），题号无法归类时回退完整目录。

## 人工队列只接真实发现

`07_review/manual-review-queue.json` 只接真实差异、冲突、不确定和缺证据发现。没有问题时 items 可以是 `[]`。缺少分轮执行本身保留在 unchecked，不为每道正常题制造人工确认项。

人工决定沿用现有决定日志和处理接口，记录问题、动作、理由、修改及时间即可，不要求人工姓名或签名。代理不能冒充人工作决定、接受风险或确认上传。现有 `review.py` 闸门侧将 `reviewed/resolved/accepted/fixed/closed/approved/passed/waived` 视为已处理；工作台待审徽标若采用更窄的状态集合，应与闸门口径分别说明，不据此声称内容已重新核验。

修复题目或标注后，对应单元在各轮中的结论失效并真实重审；其余单元可继续使用经原始任务、响应和安装事务核验的结论。处理人工队列不能把缺失的语义审核自动变为通过。


## 单题与题组局部复用（2026-11）

先完成最终格式装配，再审核当前最终批次。`prepare_round_plan` 的 `unit_bindings` 同时包含确认原文、最终批次对应行、答案、解析、大意、题型与知识标签；共享材料和组内任一真实变动影响整组，不拆分题组的盲审结论。`stage_semantic_inputs(batch_dir)` 为调度器提供只读的逐单元语义摘要，排除验证报告时间戳、来源、地区、年份、分类和难度。`filterMetadata` 中的真实题型/子类/知识字段仍保留；题文中的 `title` 与 `source` 内容不会因字段名而被抹除。提取文件顶层的原件摘要、字符数、版本和证据目录属于簿记，不会把一次局部源文刷新放大到全批；实际表格、图片与提取警告仍参与绑定。实际注入提示的规则（包括 `docs/content-labeling.md` 的解析/大意约束）都必须覆盖在审核规则摘要内。

复用引用记录在轮次的 `reuse` 中，直接指向原始真实执行的安装事务；不改旧任务 ID、字节绑定、原始响应或审核判断。程序再次验证任务、分片、响应摘要与覆盖，以及当前目标的原文引证。原证据丢失、被改动、旧计划缺少逐单元绑定、规则发生变化或目标无法归属时不背书。两轮仍验证不同真实执行；只剩局部目标时导出新的盲审任务，当前标签继续隐藏。某轮先完成并替换台账后，另一轮尚可用的判断从保留的历史台账恢复，避免把它们连带丢掉。全部单元均未变时仅重建派生比较和队列，不调用模型；已知发现与人工决定不因常规续跑而清空。

完整旧计划的受限兼容：`review.resolve_round_plan` 只在旧计划全部实际输入/旧规则 SHA 仍相同、题号与单位拓扑相同、原样本仍合法且达到 20%、原任务/原响应/回执/安装事务全部可核验时，保留原计划与原样本。新增登记的规则还必须早已完整存在于每个原冻结提示和私有规则摘要中。该路径不依赖或补写旧 `unit_bindings`，不生成新的执行 ID，也不把真实质量差异改成通过；当前只覆盖明确审查过的 v11/v9 提示契约，未来提示契约升级默认拒绝。显式 `fresh` 始终启用当前新计划重审。缺少上述整计划证明的旧记录仍按原保守规则处理。

执行完成与质量放行分开显示：已有 `execution_completed` 与明确 `continue_unqualified` 的质量差异显示“已执行，有差异”，保留未放行结论，但不伪装成模型还在审核，也不阻止本地最终格式检查。卡点诊断同样把该设计态归为 `quality_differences`（待人工判断、不阻断手动上传），不列为卡点、不建议自动修正；只有 `blocked` 的确定性阻断项才进入卡点列表。历史已完成装配和审核执行的非托管批次不倒回新增前置组装；新提交题库的授权边界保持不变。

保守边界：不能可靠定位的原文保留整篇绑定；原始答案附录、外部附件、提取异常和没有明确逐单元归属的图片观察可能影响多个单元或全批。听力转写仅在每个目标都有已验证时间窗时按完整相交段绑定；范围不明时保留全量转写。这些情况宁可扩大重审，不猜测局部来源。显式 `fresh` 仍归档并重新执行，不能通过历史恢复绕过。局部复用不替代内容验证、独立盲审、人工决定或上传授权。

回归：`python3 -m unittest workflow.test_review_local_reuse workflow.test_review_rounds workflow.test_review_rounds_recovery workflow.test_review_consensus`。新回归覆盖元数据/报告刷新、最终答案局部变更、共享材料整组失效、解析/知识/子类/标题真实变更、非听力图片证据、缺失/篡改原响应、旧批次无逐题绑定，以及无难度字段的完整两轮执行。
