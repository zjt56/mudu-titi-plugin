# Harness 运行时内容子智能体

## 用途与入口

插件运行时用原生 Harness 子会话完成需要查证的内容任务。它可以按需读取原卷行窗口、查看选中单元、检索知识点目录、检查已声明图片，再提交候选给原有程序验收。

默认接入 `structure_gate`、`preassemble`、`answers`、`explanations`、`knowledge`；`types` 只保留旧任务/局部修正兼容入口，新批次不增加独立题型模型调用。答案与解析仍优先走既有确定性直抄，成功时不调用子智能体。结构、媒体缓存和已验收单元基线仍保留。

`lib/content-agent.js` 负责会话、受控工具、恢复和预算；`app/workflow/content_agent.py` 负责持久队列、输入绑定、读快照和候选验收。`local_agent.invoke` 选择原生执行后，不在错误时偷偷切换回 CLI。结构入口在 `structure_ai.auto_classify`，通过 `content_structure` 保留整卷覆盖验收。

## 执行方式

1. 调度器按原阶段契约准备任务和输入摘要；原生执行器冻结来源、目录、实际模型路由及媒体白名单。
2. 模型先看到规则与取证目录，通过有限工具读取所需窗口。行号使用原文坐标，候选目录不是完整性证明。
3. Harness 创建或恢复同一任务绑定的子会话。模型只能调用 `content_*` 工具，不能执行命令、编辑文件、更新 manifest 或上传。
4. `submit_candidate` 保存原始候选，再运行原有阶段验收；分片不仅检查 JSON/覆盖，还逐单元检查来源、标签和语义契约。结构候选必须通过整卷检查。
5. 验收反馈带具体失败项；确定性来源/契约失败停止同输入重复调用。正式产物仍由原有导入器安装，子会话空闲、模型自称完成均不等于交付。

两轮审核仍由原流程独立执行，原生生产会话不替代审核，也不自动消除标签/基本差异。听力继续使用既有切段与转写链路，不新增文字分支对听力的依赖。

## 受控工具

| 工具 | 作用 |
| --- | --- |
| `content_read_unit` | 读取当前任务选中的单元及关联来源/题型上下文；结构任务读取候选目录项 |
| `content_read_source` | 分页读取快照内的原文、显式答案文本及任务规则引用；目录给出路径与行数，每次最多 500 行，不读取任意磁盘路径 |
| `content_search_catalog` | 在当前任务知识点目录中检索，支持分页 |
| `content_read_catalog` | 分页浏览同一目录；不允许自建标签或教材位置 |
| `content_list_media` | 列出冻结的已声明图片 ID |
| `content_inspect_media` | 用绑定模型查看白名单图片，返回辅助观察，不能作为原文/答案生成器 |
| `content_submit_candidate` | 提交候选，获取程序验收反馈；只有明确 accepted 才完成 |

图片调用核对真实文件字节、来源、路由和截止时间，拒绝链接/越界路径；结果按图片字节、路由与问题缓存，瞬时错误短暂延期。图片观察不是权威正文；Word 优先级及原卷保真规则不变。音频不通过该图片工具识别。

## 配置

插件模板 `backend/local-agent.plugin.json` 在旧 transport 配置旁增加：

```json
{
  "native_agent": {
    "enabled": true,
    "mode": "auto",
    "stages": ["knowledge", "answers", "explanations", "types", "preassemble", "structure_gate"],
    "max_tool_calls": 40,
    "max_turns": 4
  }
}
```

- `auto`：选择任务时只有宿主实时心跳有效才走原生，否则沿用原配置的执行方式。这是执行方式选择，不是模型失败后的兜底。
- `strict`：指定阶段必须走原生；宿主不可用就记录真实失败，不启动 CLI 补跑。
- `enabled: false`：后续任务沿用旧执行方式。已开始的任务仍受其绑定、取消和超时规则约束。
- 模型仍按现有 `roles > stages > default/设备当前模型` 规则选择；显式路由不合法直接报错。原生任务绑定实际 provider/model/profile，验收前再核对路由，禁止混用改变后的模型结果。
- 宿主默认最多同时执行 2 个原生任务，每个任务最多 4 次唤醒、40 次工具调用和 10 分钟；任务预算只能收紧宿主上限。媒体另有有限调用预算。到期或耗尽如实失败，不伪称通过。

## 恢复、取消与删除

同一提示、输入、路由、契约的任务复用持久身份和回执；已验收候选先本地复验，不能因为技术性重启再烧模型。恢复已有待处理消息时唤醒原消息，不重复追加任务。工具提交响应丢失时查询精确任务回执，不盲重发；没有 accepted 证明就不能宣称完成。

输入变化、删除标记、超时或宿主停止会取消任务。迟到响应不能覆盖终态。队列和媒体缓存位于源码根 `.content-agent/`，含试卷内容，已排除版本控制，不属于可发布代码。

用户明确删除批次时，先按原流程等到安全阶段边界，再清理该批次的队列、候选、媒体缓存和绑定的 Harness 持久子会话，最后删除批次/收件箱及归档。无法安全完成会话清理时拒绝删除并保留批次，不能显示删除成功。清理能力是可信宿主操作，不向模型暴露。

本方案不自动上传、发布或裁决审核差异；教材匹配仍暂停。不对准确率、速度或成本作未经实卷测量的百分比承诺。

## 验证范围

自动回归使用临时批次、模拟原生会话、模拟视觉 transport 和候选校验，覆盖路由、越权、恢复、取消、输入变化、预算、结构漏题、媒体缓存及删除闭环。模拟通过不代表真实模型已经完成试卷，也不代表准确率已经测量。真实工作台使用新代码须加载该插件版本后，才会出现原生宿主心跳；旧进程不会因修改源码自动切换。
