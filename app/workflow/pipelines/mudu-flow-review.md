# 候选审核 Harness Workflow

`mudu-flow-review.workflow.js` 是独立的 harness `workflow` 工具脚本体，不是可直接用 Node 执行的模块，也不修改现有 runner、contracts 或 review。将脚本全文传给工具的 `script`，例如工具请求的 `meta` 为 `{"name":"mudu-flow-review","description":"题目录入候选审核"}`，`args` 为 `{"batch_dir":"E:\\录题工作流\\录题skill技能\\workflows\\示例"}`。`batch_dir` 应为代理可读取的批次绝对路径，需备好原卷、正文、答案与适用媒体、题型及知识点目录；读取不到时停住或转人工。

顺序是来源识别、结构解析、建立有原卷证据的小题完整清单、每单元六项审核（内容完整、题干与题目匹配、缺题漏题及选项完整、错行上下题错位、图片完整且正确引用、按题型结构批次合并）。失败题返回 `rework_candidate` 并停止该题；通过题并行生成四路候选：知识点教材匹配、题型词数内容完整、答案解析难度、解析与文章大意（子智能体1），然后依次 AI 审核、一审、二审。二审针对小题清单抽样：整组题型（完形/阅读/任务型阅读/补全对话/信息转换/选词·短文·教材语篇填空/听力短文·长对话理解）整组为一个抽样单位、只做组级核对，其余题型按原卷顺序等间距确定性抽取 `ceil(小题数 × 20%)`；输出样本对象、原卷证据和审核结果，不是随机抽样。小题清单缺失、不确定、无覆盖证据、重复或未映射时阻断，不猜测。这里各审均为代理核对，不冒充人工。任意疑点、缺证据、代理失败或冲突均保留在 `human_queue`，当前题停止后续审核。返工只是建议，人工处理后需重新运行受影响的审核。

返回值仅在工具结果中：`source`、`units`（结构审核、返工候选、四路标签及审核记录）、`human_queue`。空来源、解析异常等返回 `blocked`；其余也始终是 `human_review_required`，因为机器结论不能证明人工和媒体审核已完成。它不写候选文件、审核文件、manifest 或正式批次，不上传、不发布；也不自动调用现有 ingest 或声称通过其闸门。将结果用于正式流程前应由人工核对，并按现有审核契约单独处理。

本地基础验证（Node.js）：

```powershell
node workflow/pipelines/test-mudu-flow-review.cjs
```

该测试模拟 harness hooks，覆盖正常路径与 20% 抽样、来源失败、结构返工、打标失败、二审冲突、小题清单缺失；不是实际模型或真实试卷端到端验证。清单完整性仍依赖代理对原卷的核查，不能仅凭模型声称的证据代替人工核验。
